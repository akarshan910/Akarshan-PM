Studio · sign-in flow

A code by email, your account only

Every path into and out of Studio, step by step. No passwords and no Google setup: Studio emails a 6-digit code to the owner’s address. Each step is tagged Studio, Email or Guard, and the grey notes say what to build. The interactive screen with every state is “Studio — sign in”.

Who can get in
  • Only the owner’s address, kept in the pm.owners table and added once at setup from OWNER_EMAIL, never in the code.
  • Sign-ups are off from day one, and codes go only to existing accounts.
  • Every database policy checks owners, so any other session reads nothing.
What the screens never do
  • Show or hint the owner’s address before sign-in.
  • Confirm whether an address owns the site: “Check your email” reads the same for anyone.
  • Say more than “didn’t work” or “expired” about a code.
Limits
  • 6 digits, single use, 10-minute expiry; a new code replaces the old one.
  • One code a minute per address; 5 wrong tries lock the boxes.
  • Cloudflare Turnstile when a code is requested, plus Supabase’s per-IP limits on checking codes.
To set up during development
  • Supabase Email provider on, sign-ups off, OTP expiry 600s. CAPTCHA (Turnstile) on once lumina’s login sends tokens too: the project is shared.
  • “Magic link” email template switched to show {{ .Token }}; custom SMTP (Resend) with SPF and DKIM.
  • Create the owner once with npm run setup:owner; turn on 2-Step Verification for that inbox.

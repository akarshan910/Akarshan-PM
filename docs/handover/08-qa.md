# 08 · QA

How to prove each item is done: pixel parity with the boards, motion, accessibility, performance, and the checks that keep drafts and secrets safe. Every milestone ends with this pass for what it touched ([README · Definition of done](README.md#definition-of-done-for-every-item)).

## Pixel parity

The boards are the reference at 1440, 834 and 390 wide. Parity is checked with screenshots of the board and of the built page **showing the same content**, compared automatically and then by eye.

### 1. Render the board

`design/tools/render-board.mjs` renders any board to static HTML and a full-page PNG, in any Tweaks state, without the canvas runtime:

```bash
node design/tools/render-board.mjs design/boards/Home.dc.html qa/boards/home-1440 '{"motion":"reduced","skills":"V0: every skill regular"}'
node design/tools/render-board.mjs design/boards/CaseStudyMobile.dc.html qa/boards/case-390 '{"state":"chapter picker"}'
```

- Event handlers are dropped, so the output is the board at rest in the requested state.
- Reduced motion is emulated, so entrances are in their final position.
- The `qa/` folder is git-ignored.

### 2. Render the page with the board's content

The boards' copy is illustrative, and V0 shows the current site's content, so a straight comparison would differ everywhere.

- **The fixture:** `tests/fixtures/board-content.ts` holds the boards' content as documents: profile, layout, the nine projects shown on the boards, and posts.
- **Using it:** the dev server and the Playwright project `parity` run with `CONTENT_SOURCE=fixture:boards`, which feeds that fixture to the same loaders instead of Supabase.
- **Where it's allowed:** never in a production build. The build fails if `CONTENT_SOURCE` is set when `VERCEL_ENV=production`.
- **Freezing the page:** `?qa=1` freezes everything random or time-based:
  - floating previews take their rest slots;
  - "Last updated" and the dashboard greeting use 13 Oct 2026, 18:00;
  - the testimonial carousel starts at 1.

### 3. Compare

`tests/parity/*.spec.ts` screenshots each section by its selector at each width, and compares it with the matching crop of the board PNG using `pixelmatch`:

| Setting | Value |
| --- | --- |
| `threshold` (per-pixel colour distance) | 0.1 |
| Allowed differing pixels per section | 0.5% |
| Masks | Inside the prototype iframe, the tilt layer while a pointer is over the hero, and live time strings |

A failure writes the board crop, the page crop and the diff image to `test-results/parity/`. Text that wraps on a different word is a real failure. Fix the CSS, not the threshold.

Fonts: the boards load Archivo, Geist, Geist Mono and JetBrains Mono from Google Fonts; the site self-hosts the same families. If a mismatch is only glyph antialiasing (the diff shows outlines of letters, not shifted blocks), raise that section's allowance to 1% and note it in the spec.

### 4. Check by eye

For every page and every state, at 1440, 834 and 390:

- overlay the two screenshots at 50% opacity, or flick between them;
- look at spacing above and below each section, line breaks in headings, alignment of the grid, icon sizes, border colours, and the empty and error states;
- check the in-between widths too: 360, 430, 768, 1024, 1280 and 1920. Nothing overflows, nothing overlaps, and no line runs past `.wrap`.

Record any intentional difference in [09](09-decisions.md) before calling the item done.

## Motion

For every ID in [04](04-motion.md):

1. **Timing.** In Chrome DevTools › Animations, check the duration, delay and easing against the spec. For CSS transitions, `getComputedStyle(el).transitionDuration` and `transitionTimingFunction` must match.
2. **Live demo.** Compare it side by side with `Motion.dc.html` (open the board in the canvas, or render it to HTML and open that).
3. **Reduced motion.** Repeat with `prefers-reduced-motion: reduce` emulated. Each animation behaves as its "Reduced" line says, and nothing moves that shouldn't.
4. **The owner's switch.** With the hero's motion switched off in the layout, there's no tilt or drift.
5. **Performance.** Record 10 seconds of moving the pointer over the hero at 4× CPU throttling: no long tasks over 50ms, and no layout or paint in the frames beyond the first.

Playwright covers the keyframes that matter for function: the phone menu opens and closes, the floaters appear and fade (with a mocked clock), and the chapter marker moves. `tests/e2e/motion.spec.ts` asserts the computed styles above for one element of each animation.

## Accessibility

WCAG 2.2 AA, on every page and Studio screen.

- **Automated:** `@axe-core/playwright` on every route and Studio screen, at 1440 and 390, in the default state and in each Tweaks state the boards show. No violations, or CI fails.
- **Keyboard:** every flow works without a mouse. That covers the nav and phone menu, skills highlight, testimonials paging, the work filters, the case study chapter sheet, the prototype frame and lightbox, sign-in, the builder outline, drag-and-drop by keyboard, the block builder, the topic picker, and every dialog. Focus is always visible, never trapped where it shouldn't be, and returns where it should.
- **Screen readers:** a pass with VoiceOver on Safari (macOS and iOS) and NVDA on Firefox. Read the landmarks and headings, the live announcements (save status, sign-in states, reordering, "Copied"), and the labels on the boards' `aria-*` attributes.
- **Zoom and text size:** at 200% browser zoom and at 400% on a 1280px window (320 CSS px), nothing is cut off and nothing needs two-way scrolling, except the tables that are meant to scroll.
- **Contrast:** every text and UI colour pair meets 4.5:1, or 3:1 for large text and UI parts. The known exceptions are listed in [09](09-decisions.md), Q5, until the owner decides.
- **Targets:** 24×24 CSS px minimum everywhere, 44×44 on touch layouts.

## Drafts never leak

`tests/e2e/no-leaks.spec.ts`, against a local Supabase, on every pull request:

1. **Seed the markers.** Seed a draft project, a scheduled post, an unlisted project, a hidden section, an outcome with evidence and an unconfirmed fact. Each contains a unique marker string, such as `LEAK-7f3a-draft`.
2. **Build the site.**
3. **Search for markers.** None may appear in any file in `build/`: HTML, JS, JSON, `sitemap.xml`, `rss.xml`, `robots.txt` or `vercel.json`.
4. **Probe as a visitor.** As `anon`, query every table and function. No marker comes back.
5. **Probe the pages.** Request each draft's URL: 404. Request the unlisted project's URL: it renders, with `noindex`, and isn't linked from anywhere.
6. **Check the preview.** Create a preview link and check its response: `no-store`, `noindex`, and the marker present. Revoke the link and check it returns 410.

The RLS tests in [06](06-backend.md#row-level-security) run in the same job.

## Security checks

On every push, in CI:

- **gitleaks** on the full history of the branch. Any finding fails the build.
- **The `VITE_` check:** no browser variable holds a service-role JWT.
- **`npm audit --omit=dev`:** no high or critical advisories.
- **CSP:** a Playwright test reads the response headers of `/`, a case study, `/preview/x` and `/studio`, and checks them against [01 · Headers](01-architecture.md#headers). No inline script runs except the hashed bootstrap.

Before launch, by hand:

- Sign in with an address that isn't the owner's: "Check your email" appears, no email arrives, and Studio stays closed.
- Use a valid code for a non-owner test account, created and then deleted in a local stack: it's signed out at once.
- Five wrong codes: the lock shows ("Try again in …") on that device; after 15 minutes, a new code works.
- Studio pages restored from the back/forward cache after signing out reload to the sign-in page.
- Lumina-photography still signs in, after every Auth setting change ([06 · Supabase settings](06-backend.md#supabase-settings)).
- After CAPTCHA protection is switched on ([09](09-decisions.md), Q8), lumina's login, SMS code and password reset still work.

## Content checks

For V0 ([07](07-v0-content.md)), before launch:

- **Verbatim:** a script compares every string in `src/legacy/content.ts` with the published documents, so nothing was lost or changed by mistake. The allowed changes are listed in 07.
- **Nothing invented:** a reviewer reads every published page against the old site. No new claims, numbers, roles or dates.
- **"Worth a check":** each item appears in Studio with its alternative.
- **Legacy links:** every `?open=` link and prototype path redirects as listed.
